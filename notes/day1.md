## Topic 2：变量与 f-string

**我理解的：**
- 变量是带名字的盒子。`name = "chris"` 把字符串 `"chris"` 装进叫 `name` 的盒子里。
- `=` 是赋值（塞值），不是等于；判断相等必须用 `==`。
- f-string 是 `f"hello {name}"` 这种字符串，**前缀 `f` 一定不能省**，否则 `{name}` 原样打印。
- `:03d` 这种格式说明符控制数字怎么显示：`3` → `003`。

**我卡过的地方：**
- 第一版只写了 2 个变量、1 行 print，Codex 抓回来让我补齐。我学到：「做了一半就提交」是工程里最常见的坑。
- 把 `days_left` 写成了字符串 `"I have 3 days left"`，被指出字符串和数字不一样，不能做数学。改成 `days_left = 3`。
- 试着加 `:03d` 时撞 SyntaxError。折腾了两次才看清：**句号 `.` 写在了双引号外面**。`"days left".)` 这种就是错的。句号、问号、感叹号除非明确是 Python 运算符，否则一律塞在引号**里面**。
- 改完之后跑通：`3` → `003`，成就感满满。

**我的疑问：**
- 数字和字符串的边界为什么这么容易踩？后面还会撞什么类似的吗？
- f-string 还能玩什么花样？比如日期格式化。

## Topic 3：`input()` 与类型转换

**我理解的：**
- `input()` **永远**返回字符串，哪怕用户输入 `18`，拿到的也是 `"18"`。
- 想做数学必须先 `int()` 或 `float()` 包一下：`int(input("..."))`。
- `:04.2f` 是数字格式化：宽度 4、保留 2 位小数。`90 / 7 = 12.857...` → `12.86`（四舍五入）。

**我卡过的地方：**
- 第一版又偷懒了，只做了 input，没做 int 转换、没做除法，被 Codex 抓回来。
- 第三行 print **忘了加 `f`**，导致 `{daily:04.2f}` 原样打印。Codex 教我一条快速诊断法：「看到 `{}` 没被替换，先怀疑是不是忘了 `f`。」这条以后常用。
- 用户输入提示语末尾要加空格，否则用户输入紧贴提示，看着挤。

**我的疑问：**
- 如果用户输入的不是数字怎么办？比如输 `abc`，`int("abc")` 会怎么样？——这个错误我还没撞过，但预感会撞。

## Topic 4：`if/elif/else`

**我理解的：**
- `if/elif/else` 让程序分支：满足条件走这条，否则走那条。
- **`if` 和 `elif` 后面能接条件，但 `else` 后面只能直接 `:`，什么都不接**。这是我亲手撞了 SyntaxError 才记住的。
- 缩进 4 个空格是 Python 语法的硬要求，不是为了好看。
- 比较运算符：`==`、`!=`、`<`、`>`、`<=`、`>=`。
- `in` 检查子串（`"weather" in "what's the weather"` → True）。
- `or` 连接多个条件，至少一边为真就为真。

**我卡过的地方：**
- 第一版写了 `else "exit or quit" in order:`——`else` 不能带条件。报错信息 `expected ':'` 现在看一眼就知道是怎么回事。
- 顺手打了个错字 `"jokee"`（多了个 e），测试时才发现。Codex 说「测试用例」才是抓这类 bug 的关键，后面要专门讲。

**我的疑问：**
- 真实的程序里，`if/elif/else` 链能有多长？十几个分支怎么维护？这种链式结构怎么避免失控？

## Topic 5：简易 Agent 模拟器

**我理解的：**
- 串起今天所有东西：`input()` 拿用户问 → `if/elif/else` 分支 → `print()` 输出。
- `.lower()` 是字符串自带的方法，把所有字母变小写，让 `WEATHER` 和 `weather` 能被同一个分支命中。这是「健壮性」的第一课。
- 我写的这个 Agent 没有 LLM，但已经具备了 Agent 的**骨架**——接输入、做推理、分支响应。后面的工作就是把 LLM 和真实工具接进来。

**我卡过的地方：**
- 写 `elif "exit" or "quit" in Ask:` 时以为是对的，结果**永远为真**——这是个隐藏很深的坑。
- Python 把 `"exit" or "quit" in Ask` 解析成 `"exit" or ("quit" in Ask)`，因为 `in` 优先级高于 `or`。`"exit"` 作为非空字符串，本身就是真值 → 整个表达式永远为真。
- Codex 给了两个修法：A 写完整子表达式 `"exit" in Ask or "quit" in Ask`；B 用元组 `Ask in ("exit", "quit")`。
- 我选了 **B**（元组版），更紧、更安全——能避免 `"I want to exit"` 误触退出。

**我的疑问：**
- 真实的 Agent 怎么判断用哪个工具？是 `if/elif` 链？还是有更聪明的方法？
- 多个 Agent 之间怎么协作？

## 今天最大的收获

不是某个具体语法，而是「**撞错自己修通**」这件事。

今天撞了 5 次错，每次都自己琢磨明白了：

1. 中文逗号 vs 英文逗号
2. f-string 忘了 `f`
3. 句号放字符串外面
4. `else` 带条件
5. `or` 优先级陷阱

每一次都是「先出错 → 看错误信息 → 回看代码 → 想为什么 → 改对」。这个节奏就是工程师的日常——代码不是一次性写对的，是改对的。
